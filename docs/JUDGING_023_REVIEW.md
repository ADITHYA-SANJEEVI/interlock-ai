## Three strongest remaining objections

1. **Judge access to the full financial/AI application.** The public explorer is
   genuinely interactive, but historical and read-only. It cannot be sold as an
   anonymous live PayPal/model service. The private application is real and
   source-backed, yet separately guarded provisioning and credentials are needed
   to reproduce new financial activity. The official functional-demo requirement
   still deserves explicit owner/judge consideration; a historical evidence
   explorer alone must not be described as fresh financial execution.
2. **Official Studio access and media rights.** Native integration is verified
   locally, but no public key/build or evaluation-media permission is established.
   Sponsor tutorial intent does not supply the missing operational permission.
3. **Scope and validation limits.** One genuine USD 1.00 controlled purchase,
   two historical cases, small local measurements and synthetic adversarial
   tests do not prove production scale, broad model quality or customer demand.

## Issues corrected or retained

No product P0/P1 defect was established in current source navigation, monetary
state classification, downloads, mobile layout or protected read access. The
Studio regression was strengthened to require native provider-grid content after
the actual harness, rather than only a React report-page flag.

Two harness/media failures were retained with diagnostics: an assertion expected
the wrong wording for absent booking and was corrected without changing UI/data;
the test video was padded after full-page screenshot resizing and was replaced
for filming by a dedicated fixed-size recording. The original failed inputs
remain local. No financial logic or evidence was changed to make checks pass.

No broad feature sprint is recommended. Resolve deployment access if available,
obtain Studio permission, preserve the stable fallback and move to video.
